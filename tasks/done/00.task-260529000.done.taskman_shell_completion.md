# taskman shell completion

## Problem statement

`taskman` is a Typer command-line interface (CLI) with 16+ subcommands (`new`, `list`, `show`, `move`, `close`, `validate`, `ready`, `waiting-on`, `search`, `worktree-status`, `ui`, `help`, `convert`, `migrate`, `finalize`, `version`) plus per-command options. Users type these by hand with no shell tab-completion. That is slow and error-prone — exact names such as `worktree-status` and `waiting-on` must be recalled precisely. Typer ships native shell completion, but it is currently disabled in the app, so there is no built-in way to turn it on. No one-step setup exists to enable tab-completion in a developer's shell.

## Scope

In scope:
- A committed, runnable setup script that enables tab-completion for the installed `taskman` command in the user's shell.
- Works for zsh and for bash.
- Idempotent: safe to run more than once without duplicating shell startup-file (rc) entries.
- Completes subcommand names and option flags.

Out of scope:
- fish and PowerShell support.
- Completing live work-item values (IDs, slugs, paths, statuses read from the tasks tree) — dynamic value completion is a separate follow-up.
- Any change to the legacy bash `plugins/agn/scripts/taskman.sh`.
- Publishing or packaging `taskman` to an index; the script targets a locally installed `taskman`.

## Acceptance criteria

1. A single setup script is committed in the repo and runs in one step.
2. After running it and opening a new zsh shell, `taskman <TAB>` lists taskman subcommands.
3. After running it and opening a new bash shell, `taskman <TAB>` lists taskman subcommands.
4. Partial completion works: `taskman wor<TAB>` completes to `worktree-status`.
5. Option-flag completion works: after `taskman list --<TAB>`, that subcommand's option flags are offered.
6. Re-running the script does not duplicate entries in the shell rc file and exits 0.
7. On success the script prints how to activate completion (restart the shell or `source` the rc file).
8. If `taskman` is not found on PATH, the script exits non-zero with a clear message.

## Quality gates

- Manual: run the script in zsh, open a new shell, confirm criteria 2, 4, and 5.
- Manual: run the script in bash, open a new shell, confirm criterion 3.
- Manual: run the script twice; confirm criterion 6 (no duplicate rc entries).
- `pytest` in `taskman/` passes — guards against regression if the CLI changes to expose completion.
- `taskman --help` and `taskman version` still work — no CLI-surface regression.

## Constraints and assumptions

- Completion definitions must derive from taskman's existing command tree, not a separately hand-maintained list of subcommands — a parallel list would drift as commands change.
- Assumes `taskman` is installed and on PATH (for example via `uv tool install`, `pipx`, or `pip install -e`).
- The script must not require network access.

## Summary

Closed 2026-05-29.

### Steps completed

1. Diagnosed root cause: `taskman/src/taskman/cli.py` built the Typer app with `add_completion=False`. In Typer 0.26.2 that flag disables the whole completion subsystem — both the `--install-completion`/`--show-completion` options and runtime completion-class registration.
2. Removed `add_completion=False` (one line). Verified the live command tree now completes: `taskman <TAB>` → 17 subcommands, `taskman wor<TAB>` → `worktree-status`, `taskman list --<TAB>` → option flags.
3. Documented the native install command in `taskman/README.md`.
4. Added `taskman/tests/test_completion.py`. Full suite: 216 passed.

### Changes made

- `taskman/src/taskman/cli.py` — dropped `add_completion=False`.
- `taskman/README.md` — "Shell completion" section: run `taskman --install-completion` once per shell.
- `taskman/tests/test_completion.py` — new. Guards (a) completion stays enabled, (b) `--install-completion <shell>` writes the completion files.

### Notable decisions / deviations

- **Setup script dropped (deviation from scope).** A committed `install-completion.sh` was built, then deleted. It produced byte-identical completion stubs to Typer's native `taskman --install-completion` (verified by diff), so it added no completion capability — only one-step both-shells install plus a PATH check. It was also not shipped in the wheel (`pyproject.toml` packages only `src/taskman`), so direct-from-GitHub installs could not use it. End users now run `taskman --install-completion` (works for clone, pip, pipx, and uv installs).
- Script-specific acceptance criteria (1 committed script, 6 idempotent rc edits, 7 activation print, 8 PATH check) are superseded by Typer's native installer, which is idempotent and prints activation instructions itself. Completion-behavior criteria (2–5) are met by the native command.
- **Shellingham caveat.** Typer auto-detects the shell via shellingham; it works in a real interactive terminal but failed in the non-interactive agent harness. Explicit per-shell install stays available via `_TYPER_COMPLETE_TEST_DISABLE_SHELL_DETECTION=1 taskman --install-completion <shell>` (used by the hermetic test).
